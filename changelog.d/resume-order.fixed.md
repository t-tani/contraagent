A resume gives the flow the results of the tasks it skips one at a time, in the order the journal of the earlier attempts recorded them, so flow code that depends on the order in which its tasks finish (`asyncio.as_completed`, a list it appends to as each `await` returns) creates the same tasks again. Before, the skipped results came in the order the flow created the tasks. A task whose fingerprint is complete only when it starts (it declares `outside_state` or `output_of`, or it reads an output the flow did not receive) is skipped as soon as the tasks it waits for are done; before, it waited for a free slot, and a deadline could defer it. A task that fills in another task's file (`output_of`) takes the file's content as it was when the task was about to start into its fingerprint, not the fingerprint of the task that wrote the file. A resume skips it when the file is as it, or a task after it that fills the file in, left it (the new journal field `output_of_after`), so a file edited by hand runs again every task after its writer that fills it in. Fingerprints are made in a new way, from the digest of each part of a task's work: resuming a run of an earlier contraagent runs every task once again, and a recording imported from such a run is not played: import one from a run of this release instead.
