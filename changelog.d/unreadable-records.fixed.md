A resume no longer runs every finished task again, with `ok=True`, when the journal cannot be read: a journal was taken for empty then, and a run id that held a run could also be started again without `RunExists`. A journal or a `run.json` that cannot be read now raises `ContraagentError` before a task runs (`EarlierRunError` from `resume_from`, `RecordingError` from an import of a recording). So does a `run.json` that is empty or does not parse, which got a new `run_uid`. An empty `cursor.json` raises `ValueError` from `CursorStore`, as a malformed one did, where it started the cursor afresh. A journal line that does not read is a warning with its line number.
