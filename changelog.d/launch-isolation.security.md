A launch on any credential but `ambient` now leaves out every variable of the host that holds a secret by one rule: a word of its name ends with `KEY`, `TOKEN`, `SECRET`, `PASSWORD`, `PASSWD`, `PASSPHRASE` or `CREDENTIAL(S)`, or is `PAT` or `AUTH`, or its value is a URL with a password (a proxy variable keeps its password). The rule removes `GITHUB_TOKEN`, `GH_TOKEN`, `NPM_TOKEN`, `HF_TOKEN`, `AZURE_CLIENT_SECRET`, `DATABASE_URL` with a password and `SSH_AUTH_SOCK`, which the former list of name endings let through. A task that needs one of them, such as one that pushes over SSH or runs `gh`, gets it through `Pipeline(env=...)`. On Linux the pipeline's process also makes itself unreadable to the agents it starts (`PR_SET_DUMPABLE`), so an agent cannot read every hop's credential from its `/proc/<pid>/environ` or memory; it writes no core dump, and a profiler attaches to it only as root. The security topic now states what a task agent can still reach as the same user: the user's files under `HOME`, and the environment of other processes that hold a secret.
