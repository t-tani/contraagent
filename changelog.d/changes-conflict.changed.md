Two tasks whose `changes` patterns may cover the same files never run at once: the queue starts neither while the other runs, so a failed attempt's removal of the files it created never takes the other's, and each file's change is one task's. This holds for every task the flow creates, also those after an `await`, which `contraagent check` does not see. The patterns are read as a file system that tells names apart by neither case nor Unicode form reads them (`Docs/**` covers `docs/a.md`), with a `?` or a set read as `*`, and two tasks in directories of which one is under the other are compared from the one above. `{unit}` in the patterns lets the tasks run together. `contraagent check` now says which tasks run one at a time for this. A runner of `WorkQueue` may say which tasks conflict (`conflicts(task, other)`), and the starvation guard counts a conflict as it counts a claim. The Lean specification proves that no task runs beside one it conflicts with, and that the test of two patterns misses no file.
