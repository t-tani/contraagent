A task that comes after one the runner defers as it would start (its credential rests) now launches, whatever order the queue met the two in. When the queue met the later task first, as in a time box's endgame, where a finishing kind comes first, and nothing else ran, that task was deferred as `dependency_not_queued`; while other tasks ran, it waited up to a second with a slot free. A pass that finishes a task without a launch is now followed by another pass at once
