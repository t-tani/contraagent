A resume runs again a task that was running when the run's process ended. When an earlier attempt of the task had finished with the same fingerprint, and the attempt that was cut had written an output that reads, the resume skipped the task on that output, which no finished attempt had left. The marker a run keeps of each running task (`inflight/<key>.json`) now holds how many rows the journal held when the task started (`journal_rows`), and a marker left with no journal row since runs the task again; its journal row's `rerun` says so
