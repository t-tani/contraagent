The monitor tells data from order and from creation: an edge of the pipeline graph is solid for `given_from` (the later tasks were given the earlier ones' output), dotted for `after` alone (order only) and dashed for `created_from`; a highlighted unit rings the tasks joined to it in the style of their link; a task's earlier and later tasks carry their lineage (`UpstreamTask.lineage`, `DownstreamTask.lineage`), and its earlier tasks now include those it was created from. A task's input files are its `InputFile` params (`TaskIO.input_files`: path, hash, the task whose output file it is, and the check at the start); the files of an input contract are "Checked files it reads". The monitor also shows where a failure stopped a flow call (on the failed task and on the flow call's mark), the tasks no flow awaited, a rerun's changed fingerprint parts and a divergence, and counts cancelled tasks as finished everywhere, never among failed attempts (API 3.7.0).
