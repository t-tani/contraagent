A resume now compares the outputs a task reads by their content in a flow that does not wait, as it already did in an async flow. A task given another task's `Pending` takes that task's output file as it is when the task is about to start into its fingerprint, not that task's fingerprint. So a task that runs again and writes the same output leaves the tasks that read it skipped, and an output file changed under a skipped task runs again the tasks that read it, where before they reused results made from the old output. A resume also runs again a task whose output file no longer reads under its output schema, its journal row's `rerun` saying so, where before the flow received `TaskFailed` (`invalid_output`) at the `await`. A task that only waits for another (`after=`, or the writer of the file an `output_of` task fills in) still takes that task's fingerprint. Resuming a run of an earlier contraagent runs each task given a `Pending` in a flow that does not wait once again.
