The preflight's line about omp's own model chain reads omp's global config from the directory that `omp config path` reports, and waits for that command however long it takes. When the command failed or took more than 30 seconds, the preflight read `~/.omp/agent/config.yml` instead, which is the wrong file under `PI_CODING_AGENT_DIR`, `PI_CONFIG_DIR` or a profile, and it then said that no `retry.fallbackChains` was configured. It now says `not known: omp config path failed: <the last line of its error output>`. The command also runs the omp binary the backend was given, not the first `omp` on PATH.
