`contraagent hub prune --dry-run` changes nothing in `--streams-dir`, so it is safe beside a running hub, as its documentation says. It opened the directory as a starting hub does: an open segment that the hub was appending to lost a line that had no end yet, and one with no whole line was deleted. A dry run now reads the sealed segments and their index only. Without `--dry-run`, the command and the operations guide now say to run it only while no hub uses the same storage, also a hub with no retention: the command recovers the open segments and removes segment objects that a running hub may be writing
