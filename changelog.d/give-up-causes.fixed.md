A task that nothing can launch is deferred with the cause that is true of it, and the tasks after it are not deferred with it. When nothing ran and no pass could start what was queued, every queued task was deferred as `dependency_not_queued`, which the monitor words as an earlier task that was never scheduled: also a task whose claim capacity is 0, tasks that wait for each other, and every task that only came after one of these. Now a task whose dependency was never queued is deferred as `dependency_not_queued`, one that finds a capacity of 0 as `no_capacity`, and tasks that wait for each other as `dependency_cycle`; a task that only waits for one of them starts once that one is deferred, as after any deferral
