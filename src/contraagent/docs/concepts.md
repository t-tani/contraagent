# Concepts

Each word below has exactly one meaning: in the Python API, in the files a run
writes, in the monitor's HTTP API, in the web components and in this
documentation. No other word is used for the same thing.

"In code" names the code by its name (`Task`), by its public path where that says
more (`contraagent.engine.Run`), or by a file. A name a public module exports
(`contraagent`, `contraagent.config`, `contraagent.backends`, `contraagent.engine`,
`contraagent.plugins`, `contraagent.monitor`, `contraagent.monitor.api`,
`contraagent.testing`) is found there, and its `__module__` names that module; any
other name is implementation, not public ([Compatibility](compatibility.md)), and is
named for whoever works on contraagent itself.

## Work

| Word | Means | In code |
|---|---|---|
| **coding agent** | the CLI program that does the work (`claude`, `omp`, `opencode`, `pi`, `codex`) | `agent` in config, routes, journal and monitor; `Backend` is its Python adapter |
| **LLM** | the language model the coding agent runs on, nothing else | `model` |
| **agent task** / **Python task** | a task a coding agent executes / one this process executes | `agent_task`, `@python_task`; `Task.executor` and on disk `executor: "agent" \| "python"` |
| **kind** | the class of work (`summarize`); a Python task's kind is its function's name unless its declaration names another | `Task.kind`, `agent_task(kind)`, `@python_task(kind=)` |
| **unit** | what a kind is applied to (`alpha`): it names a task and its output, and locks nothing | `Task.unit`; an agent task call's first positional argument; a Python task's parameter named `unit` |
| **claim** / **claim capacity** | a name a task holds while it runs, its declaration a template (`topic:{unit}`, `topic:{params.topics}`: one name per element of a list); one task holds a name at a time / how many running tasks may hold one name instead, given by the name or by an `fnmatch` pattern that gives each name it matches a capacity of its own: a number, or what one running task that claims the name needs of the host (memory, cores), worked out from the host's free memory and usable cores each time such a task would start | `agent_task(claims=)`, `@python_task(claims=)`, `Task.claims`; plan `claims` / `claim_capacity`, `[defaults.claim_capacity]`, `PerTask`, `ClaimCapacity`, `WorkQueue.capacity` |
| **service** / **service address** | the long-lived helper a claim name stands for (a worker service, a database, a local server), given by a function of the name that returns a context manager: the first task that claims the name starts it, every task that claims it shares it while it runs, and the run's end stops it; a start that fails fails the tasks that claim the name, for the rest of the run or for its cool-off; a task a stub run plays holds none / the string its start gives, by which a task that claims the name reaches it | `Pipeline(services=)`, `Service`, `Pipeline(service_cooloff_s=)`, `service_address`, `CONTRAAGENT_SERVICE_<NAME>`; `services.jsonl` (`ServiceEvent`); monitor `Plan.services` (`ServiceSpan`) |
| **task** | one kind applied to one unit | `Task` |
| **key** | a task's stable identity: an agent task's is `<kind>-<unit>` (`<kind>` with no unit), a Python task's `python:<kind>-<unit>` (`python:<kind>` with no unit), or the `key` of its call options; the n-th task a flow call creates under one key is `<key>~n` | `Task.key`, field `key` everywhere, monitor URL `key`; as the name of its files (`streams/`, `contracts/`, `calls/`, `inflight/`): `file_name(key)`, every character but a letter, a digit, `-`, `_` and `.` turned into `_` |
| **params** | what a task is given, copied as JSON at the call, so what the flow does with a value afterwards does not reach the task: for an agent task, the instance of its `params=` model that its task call passes (none when it declares no model), as the JSON of its fields; for a Python task, the arguments of its task call bound to its function's parameters, the unit aside; a `Pending` among them, at any depth, and a value that is not JSON raise `TypeError` at the call | `Task.params`, `AgentTask.params`, call file `params`, `CONTRAAGENT_PARAMS` |
| **input file** | a file a task is given as a param, by its path and the SHA-256 of its content, taken at the task call: a file of the working directory, or an output file of the run; the params hold both, so both are in the fingerprint, and the task is refused (`invalid_input`) when the file no longer has that content as it starts. A path outside the working directory and the run's `out/`, itself or through a symbolic link, raises `ValueError` at the call | `InputFile`; params value `{"path", "sha256"}`; journal `fingerprint_parts` `input_files` |
| **call options** | the words of a task call beside its params: `key`, `after`, `priority`, an agent task's `credential`, and `cancellable`; `task.options(...)` gives them, for an agent task and a Python task alike, and returns the same task with them, so `task.options(key=k)(unit, ...)` is a task call; an option it does not give keeps the value it had (none at first), and None as `key` or `credential` clears it. They are not part of the task's declaration, and but for `key` not part of its fingerprint | `AgentTask.options`, `PythonTask.options` |
| **flow** | the function that calls the tasks: a plain function, which creates tasks that are independent or ordered with `after=` only, or an `async def` function (an async flow) when a task is given another's output, which awaits task calls, flow calls, `time_box`, `asyncio.gather` and `asyncio.TaskGroup`; its code runs on the flow loop, so what needs a clock, threads or I/O is refused where it is called | `Pipeline.run(flow, ...)`, `await Pipeline.run_async(flow, ...)` from async code |
| **flow call** | one run of an `async def` flow: the top flow, or an asyncio Task created on the flow loop while a flow call's code runs; it waits at each `await` for tasks or other flow calls; ids `0`, `0.1`, `0.1.2`, ..., a child's id its parent's and its number in the order the parent created it, from 1, every asyncio Task taking a number; it is on record (`flow_calls.jsonl`, the monitor) once it creates a task or a flow call or ends with an error of its own (a task's `TaskFailed` or `TaskDeferred` passing through it unchanged is not), a top flow call from its start, so a Task that only waits for a task already created leaves no record and the ids on record may skip numbers; a flow that does not wait is flow call `0`; its state is `running` until it `returned`, `raised` or was `closed` (cancelled: by a failed sibling in its `TaskGroup`, past its time box's grace window, at the run's end, or when it waits for what nothing will answer, with an error that names where it waits); one that raised records where the exception left its own code and the key of the failed task the exception is, if it is one; a flow call goes on when its parent ends, returned or raised, and the run waits for every flow call to end | `FlowCall`, `FlowDriver`, `FlowCall.state`, `FlowCall.raised_at`, `FlowCall.raised_by`; `flow_calls.jsonl` (`FlowCallRow`, its end's `raised_at` and `raised_by`); monitor `Plan.flow_calls`, `FlowCallNode` |
| **flow loop** | the event loop flow code runs on: callbacks that are ready to run, in order, and no clock, no threads and no I/O, so an `await` that needs one raises `TypeError` there; the run lets the flow calls run until none is ready (every flow call waits for a task or for another flow call) before it starts what they queued | `FlowDriver.settle`, `FlowDriver.settle_here` |
| **flow error** | an exception of flow code's own (a bug, `TooManyPasses`; not a task's `TaskFailed` or `TaskDeferred` passing through) that a flow call raised, listed once, for the flow call it started in, even when a parent caught it with `asyncio.gather(..., return_exceptions=True)`; or any other exception a top flow call raised after its first task was queued; or the error that closed a top flow call that waited for what nothing would answer; a run with one is not ok; the run keeps going past it and past a failed task: a failure stops only the code that awaits its output and the flow calls that await that code, never another flow call or a task, and the run ends not ok once it has done all it can (see [Failures](tasks.md#failures-the-run-keeps-going)) | `RunReport.flow_errors` |
| **origin** | where a flow created a task: its flow path (with each loop's pass), created from, given from and flow call | `Task.origin`, `Origin`; plan `flow`, `created_from`, `given_from`, `flow_call` |
| **flow path** | the frames of flow code that created a task, outermost first, across flow calls; a flow call's flow path is its parent's where the parent created it | `Origin.flow`, `Frame`; plan and flow call `flow`, the monitor's too |
| **call site** | where a frame of the flow path was when the task was created: function (`module.qualname`), file and line; a flow call's site is where its parent created it | `Frame.function`, `.file`, `.line`; `FlowCall.site` |
| **loop** | a `for` or `while` statement in flow code, named by its first line; a call site's loops are those whose pass it is in, outermost first; a comprehension is not a loop | `Loop.line`, `Frame.loops`; `flow[].loops[].line` |
| **pass** | one iteration of one loop, numbered from 1 each time the loop is entered; never an attempt, never the `~n` of a key | `Loop.pass_`, `flow[].loops[].pass`; `max_passes` (the passes a `while` loop may make; a `for` loop has no limit), `@max_passes(n)` (the passes each `while` loop of one `async def` function of flow code may make, in place of the run's), `TooManyPasses` |
| **created from** | the keys of the results that reached a flow call between its previous resume and the resume in which it created a task: of each task it awaited (an await of a result given before resumes it at once), of the items of a `gather` or `TaskGroup` it awaited, and the created from of a flow call it awaited, as that flow call ended | `Origin.created_from`, `FlowCall.frontier` |
| **given from** | the keys of the tasks whose outputs a task was given in its params: of the outputs the flow had received when it created the task, each one whose JSON is a value of its params, at any depth, whole, or one whole item of which is (an output that is a list, a Rows); so a copy of an output counts as the output, and a field or a text taken out of it, or a value built from it, does not (the task's created from still shows that it came after); an input file that is a task's output file counts for that task; shown only, never part of the fingerprint or of what a resume skips | `Origin.given_from`; plan `given_from`, monitor `PlanNode.given_from` |
| **unawaited task** | a task whose task call's `Pending` no flow awaited, gave in `after=` or returned: it ran all the same, for its output file and its changes; information, never an error | `FlowCall.unawaited`; the end of a top flow call in `flow_calls.jsonl` (`FlowCallRow.unawaited`), once every flow call it started has ended; monitor `FlowCallNode.unawaited` |
| **fingerprint** | a digest of what defines a task's work: kind, unit, key, its params as JSON (an output it was given among them, by its content; an input file by its path and hash), its definition (instructions, role file, its plugins' skills, schemas, validators; a Python task's source), for an `output_of` task the content of the file it fills in as it was when the task was about to start, and its outside state when it declares one; neither a task it waits for with `after=` nor where its params came from (given from) is part of it, so a task that runs again and writes the same output leaves the tasks given that output as they were; a digest of each of these parts is kept beside it, so a resume names the parts that changed; resume skips a key whose last journal row is ok with the same fingerprint and whose output still reads under its output schema, but not a task declared `rerun_on_resume`, nor one whose last result was partial | `Task.fingerprint`, `Task.fingerprint_parts`, journal `fingerprint`, `fingerprint_parts` (`definition`, `params`, `input_files`, `outside`, `output_of`); `AgentTask.digest`, `PythonTask.digest` |
| **outside state** | what a task's work depends on beside its params and its definition (a state file the pipeline keeps, files another process wrote, or what a task it waits for with `after=` changed), as the JSON value a function of its unit and params returns; called when the task is about to start, its value's digest is part of the task's fingerprint, so a resume runs the task again when it changed; a function that raises refuses the task | `agent_task(outside_state=)`, `@python_task(outside_state=)`, `OutsideState`, `Task.outside`; journal `outside` |
| **rerun** | a task a resume runs again although an earlier attempt of the run finished it, and why: its outside state or other parts of its fingerprint changed (each named), a divergence, its output no longer reads under its output schema, the file it fills in (`output_of`) is not as the earlier attempts left it, its last result was partial, or its kind is declared `rerun_on_resume` | journal `rerun`, monitor `PlanNode.rerun`; `rerun_reason` |
| **divergence** | a rerun whose params differ from its key's journal row although every task it was given from or created from was skipped in this resume, and whose input files did not change: the flow's code took another path for the same outputs (a clock, randomness, outside state, or changed code); its fingerprint keeps a wrong output from being used, so it costs a run of the task, never a wrong result | journal `rerun` (`divergence: ...`), the warning `[resume] <key>: divergence: ...` |

## Definition

| Word | Means | In code |
|---|---|---|
| **interface** | what an agent task takes, produces and may spend | `agent_task(params=, output=, max_turns=, ...)` |
| **implementation** | how an agent task is done: a plugin directory, with the skills of the skill plugins it names. One declaration may name several by name, each a kind of its own | `agent_task(plugin=)`, `agent_task(implementations=)`, `Plugin` |
| **base kind** | the kind a declaration of several implementations names (`review`); each implementation is the kind `<base kind>-<name>` (`review-go`), takes the base kind's task table below its own, and is drawn in the base kind's group; no other declaration may have the base kind or an implementation kind as its kind | `agent_task(implementations=)`, `Implementations`, `kind_clash`, `AgentTask.base_kind`, `Task.base_kind`; `plan.jsonl` and definition `base_kind` |
| **skill plugin** | a plugin that holds skills and nothing else that acts; tasks with different plugins load it to share its skills | `agent_task(skills_from=)`, `Plugin.skills_only` |
| **role** | a named agent definition in a plugin: its procedure | `agents/<role>.md`, `Launch.role`, Claude Code's `--agent` |
| **instructions** | text before the call protocol, for an agent task with no plugin | `agent_task(instructions=)` |
| **hook** | a hook inside the coding agent, declared by a plugin; nothing else | `hooks.toml`, `contraagent plugin render` |
| **MCP servers** | the MCP servers an agent task's coding agent gets: its plugin's `.mcp.json`, or what the pipeline's function returns for the task; never the user's or the project's | `.mcp.json`, `Pipeline(mcp_servers=)`, `McpServers`, `Launch.mcp_config` |
| **call file** | the params and output contract handed to one agent task | `CallFile`, `runs/<run>/calls/<key>.json` |
| **changes** | the files one attempt created, modified or deleted under the patterns its task declares (but those a `!` pattern leaves out), beside its output; the files a failed attempt created are removed, or kept when its kind keeps them | `agent_task(changes=, keep_failed_changes=)`, `TaskAdapter.changes`; `Changes`: `TaskResult.changes`, journal `changes` (`removed`, `kept`) |
| **final message** | the agent's last message of a launch; an agent task whose output is its final message has it written to its output file and checked there | `LaunchResult.result_text`; `agent_task(output_from="message")`, call file `output.from`, `OutputContract.from_message` |
| **unwrap** | taking the JSON document out of a final message that wraps it (a sentence before it, a fence around it): the output is the document, the whole message is kept beside it | `agent_task(unwrap=True)`, `OutputContract.unwrap`, `unwrap_json`; `<output>.message.txt`; `LaunchResult.unwrapped` |

## Checking

| Word | Means | In code |
|---|---|---|
| **schema** | the pydantic class a file is checked against | `agent_task(output=)`, `OutputContract.schema`; call file `params_json_schema` (the JSON Schema of a task's params model) |
| **rows** / **row** | an output that is a JSON Lines file, each line one instance of a pydantic model, checked line by line (a line that fails names its number) / one such line, the model's instance (a row of a log, a journal row, is the same: one JSON object on one line); as a value, a list of the rows in the file's order: what the flow receives, validators are given and a task it is passed to gets | `agent_task(output=Rows[Row])`, `Rows` (a `list`), `RowsFile`; call file `output.format: "jsonl"`, `json_schema` that of one row; monitor `ContractSpec.format` |
| **example** | the value an output declares for a stub run, by one rule at every part of its JSON Schema: the first entry of that part's `examples` (a model's own, `model_config = ConfigDict(json_schema_extra={"examples": [...]})`; a field's, `Field(examples=[...])`; a text output's, `Annotated[str, Field(examples=[...])]`), else the smallest value that part accepts; in each of its strings, `{unit}`, `{key}`, `{kind}` and `{params.<name>}` are the task call's, as in a claim; it must pass its own schema. The example of rows is one row, its model's | `writes_example`, `contraagent run --stub`; `contraagent check` reports one that fails its schema |
| **validator** | a check a file must pass beyond its schema; it may also take, by keyword, the task's `params`, its `call` file, its `cwd`, and `before` (the file as it was before the task) | `agent_task(validators=)`, `CommandValidator`, any `(path, value) -> errors`; `CONTEXT` |
| **contract** | a file plus its schema and validators | `OutputContract`, `InputContract` |
| **preserve** | the parts of an output file a launch must keep as they were before it: JSON pointers (RFC 6901, a segment `*` for every member), each value they select in the file before the launch equal in it after | `agent_task(preserve=)`, `OutputContract.preserve`; call file `output.preserve` |
| **output of** | the output file of another kind's task for the same unit, which an agent task writes in place of a file of its own; the task waits for the latest task created before it that writes that file; a resume skips it only when the file is as it, or a task after it that fills the file in, left it | `agent_task(output_of=)`, `AgentTask.output_of`; definition `output_of`; journal `fingerprint_parts` `output_of`, `output_of_after` |
| **check** | what can be found wrong with a flow without a launch | `Pipeline.check`, `CheckReport`, `contraagent check` |
| **reachable kind** | a kind whose task declaration an async flow's code refers to, directly or through the functions, modules, closures, containers, classes of flow code (their methods, static and class methods, properties, bases) and instances of them it refers to; checked, routed and probed before the first launch. A candidate, not a use: of two declarations of one kind, the one whose tasks are created is the kind's | `reachable`, `CheckReport.later_kinds` |
| **stub agent** | a coding agent that plays scripted replies instead of an LLM, for tests | `contraagent.testing.StubAgent` |
| **stub run** | a run in which no coding agent is launched: the stub agent plays its tasks (agent tasks, and Python tasks but the kinds it executes: names or `fnmatch` patterns, `*` for every one), or a replay plays its tasks' recordings (but the Python task kinds it executes); flow code runs as in any run | `Pipeline(stub=)`, `StubAgent(default=, execute=)`, `writes_example`, `contraagent run --stub --execute PATTERN`; `run.json` `stub` |
| **recording** | what one task attempt left behind, kept to be played again: for an agent task, the facts of its last launch, the final contents of its outputs, the files its `changes` patterns saw created, modified and deleted, and its transcript; for a Python task, how its call ended and its output; and its task's fingerprint; never the rest of the working directory. A file over the cap is kept by its hash and size only, and its task's recording cannot be played | `Pipeline(record=, record_max_file_mb=)`, `contraagent run --record DIR --record-max-file-mb N`; `<DIR>/<kind>/<key>.json` (`by_hash`); `Recorder` |
| **replay** | a run whose tasks play their recordings in place of a launch or of a Python task's function, attempt by attempt, with nothing spent; the Python task kinds it executes (`execute`, as in a stub run) run their functions. A replay is a stub run: its `run.json` says `stub`; with `record_missing`, a task with no recording launches or runs as in any run and is recorded into the same directory, and the run is no stub run | `Pipeline(replay=, execute=, record_missing=)`, `contraagent run --replay DIR --execute PATTERN --record-missing`; `Replay`, `ReplayAgent`; `run.json` `replay`; a played attempt: `TaskResult.replayed`, `JournalRow.replayed` |
| **imported recording** | a recording made from the run directory of a run that was not recorded: for each task whose last attempt finished ok or partial, one attempt with its output files and changed files as they are now, the facts the journal and the launches recorded, and the fingerprint its journal row holds; a replay plays it only for a task of its own key and that fingerprint, and the import lists the tasks it leaves out | `contraagent.import_recording(run_dir, directory)`, `RecordingImport` (`imported`, `unfinished`, `not_imported`), `contraagent recording import RUN_DIR DIR`; the entry's `imported` (`run`, `run_uid`, `imported_at`) |
| **undeclared change** | a path of the working directory a recording run created, modified or deleted that no task's outputs or `changes=` patterns cover (`.git`, `__pycache__`, the recordings and the run's own files left out): a replay cannot make it again. Tasks run at once, so it is the run's, not a task's | `<DIR>/undeclared.json` (`run`, `created`, `modified`, `deleted`); the warning `[record] undeclared change: <path>`; `Recorder.start`, `Recorder.finish` |

## Routing

| Word | Means | In code |
|---|---|---|
| **task table** | one kind's `[tasks.<kind>]` table in the config; an implementation kind's starts from its base kind's | `PipelineConfig.task_tables()`, `resolved_task_tables`, `TASK_TABLE_KEYS` |
| **pipeline table** | a pipeline's own table in the config, read by its code; contraagent never checks its keys | `[pipeline.<name>]`; `contraagent.pipeline_table(name)` in a run or in flow code a check builds (`NoCurrentRun` outside both), `PipelineConfig.table(name)` |
| **`[defaults]`** | run-wide routing, including `[[defaults.fallbacks]]` | `PipelineConfig.defaults()`, `.fallbacks()` |
| **routing plan** | how each kind is routed (not `plan.jsonl`) | `RoutingPlan` |
| **`KindConfig`** | one kind's resolved routing and budgets | `RoutingPlan.configs` |
| **route** | one entry of a kind's failover chain: a coding agent, a model and a credential, labeled by its place in the chain (`hop 2/3 omp/m2`); a failover hop may name the stops of an earlier hop's launch it is for (every stop when it names none), and a task whose launch ended on another stop passes it over | `Route`, `Route.stops`, `Router`; `[[...fallbacks]] stops`; journal `route` (the last hop's, or the hop whose stop the attempt ends on) |
| **hop** | one launch of an attempt on one route; an attempt that fails over has one hop per route it launched on | `Hop`: `TaskResult.hops`, journal `hops` |
| **budget** | the turn, time, cost, context and stall caps of a launch | `max_turns`, `timeout_s`, `context_budget`, ...; `Limits`, `Launch.limits` |
| **credential** | the identity (and so the account) an agent's API calls are billed to | `[credentials.<name>]`, `Credential` (each kind of credential a subclass), `Launch.credential`; for one task, the `credential` of its call options (`Task.credential`, plan `credential`) |
| **trait** | a label on a credential that a task may require (`zdr`) | `traits`, `agent_task(requires=)` |
| **pool** / **gateway** | several credentials used as one / your own endpoint (LiteLLM, a proxy) | `Pool`, `Gateway` |
| **ambient** | the built-in credential: the host's own setup, untouched | `AMBIENT` |
| **quota** | a subscription's utilization of its 5-hour and weekly windows (and a model's own windows), as the coding agent reports it: account-wide. One reading is a `QuotaReading`, one window of it a `QuotaWindow`; the two windows a quota cap names are `five_hour` and `seven_day`, each with its words and length in one table | `QuotaReading`, `QuotaWindow`, `WINDOWS`; `LaunchResult.quota`, journal `quota`, `Backend.usage_reading` |
| **quota refusal** | a launch refused for its quota (a 429), with the cool-off the provider stated; not a reading | `QuotaRefusal` (`retry_after_s`), `LaunchResult.quota_refusal`, `quota_refusal`; stop `rate_limited` |
| **account** | the billing account a quota reading is of, as a 12-hex-digit digest of its login's UUID or of the credential's secret, never the value itself; one credential can stand for two (`ambient` on two coding agents, a token replaced between runs), and a credential's rests are judged by the readings of the account a launch as it bills | `QuotaReading.account`, `Backend.account`, `account_digest` |
| **quota cap** / **quota rule** | the utilization past which a credential rests / a domain's own test of a credential's latest quota reading | `max_five_hour_pct`, `max_seven_day_pct`, `QuotaCap` (`run.json` `quota_caps`, monitor `Plan.quota_caps`) / `Pipeline(quota_rule=)` |
| **rest** | not launched on for a time: a hop or a pool member after a 429, a credential past a quota cap or rule until its window resets, a credential a launch was refused as (`auth_failed`) on that launch's coding agent and model for the rest of the run; a task takes the next hop; with none left it ends `rate_limited` after 429s, is deferred (never launched) when its credentials rest on their quota, and fails `auth_failed` (never launched) when they were all refused. A credential's rest is recorded as data (`Rest`: window, reading, cap, what the rule said, or the refused stop, coding agent and model; and until when) as it begins and ends | `Router`, `CredentialPool`, `CredentialRests`, `Rest`; `rests.jsonl` (`RestEvent`); monitor `Plan.rests` (`CredentialRest`) |
| **preflight** / **preflight policy** | one probe of each distinct route of the reachable kinds before the first launch: a route its coding agent does not list, or whose probe does not complete, is dropped / what happens to a kind with no route left: `substitute` (it runs on the first route that answered, of its own credential), `stop` (the run is refused, nothing launches), `off` (no probe) | `Pipeline(preflight=)`, `[defaults] preflight`, `contraagent run --preflight`, `PreflightStopped`; `run.json` `preflight` and `Plan.preflight` (`PreflightRecord`: `DroppedRoute`, `Substitution`, `KeptKind`) |
| **skipped hop** | a hop an attempt passed over without a launch because its credential rested; not one of the attempt's hops, which are launches | `SkippedHop`: `TaskResult.skipped_hops`, journal `skipped_hops`, a deferral's cause `rests` |

## Running

| Word | Means | In code |
|---|---|---|
| **engine** | the parts underneath `Pipeline` that run tasks on their own: the runners, the queue, the flow driver, a run's directory and cursor, the routing | `contraagent.engine` (`Run`, `AgentRunner`, `RetryingRunner`, `PythonTaskRunner`, `TaskAdapter`, `WorkQueue`, `FlowDriver`, `CursorStore`, `RoutingPlan`, `Router`, `run_until_valid`); `RunnerConfig`: what `WorkQueue` reads of a task's config (`max_concurrent`) |
| **launch** | one run of a coding agent, and its result | `Launch`, `Backend.run`, `LaunchResult` |
| **light launch** | the launch of an agent task declared with no tools: its role's text (or its instructions) replaces the coding agent's system prompt, its params and output schema are in the prompt, no plugin, settings or MCP server is loaded, and its final message is its output | `agent_task(tools=())`, `AgentTask.light`, `KindConfig.light`, `Backend.light_launch` |
| **tokens** | what API calls took and gave: input, output, cache read, cache write, and the calls; a launch's calls one by one, and summed over a launch, a hop or an attempt | per call `CallUsage`, a launch's calls `Usage`; summed `TokenUsage` (`Usage.totals()`, `Hop.usage`, `JournalRow.usage`); per model `ModelUsage` |
| **resident** | the whole input of an attempt's first API call: what the coding agent loads before the task starts | `TokenUsage.resident`, `Usage.resident` |

The runners: `AgentRunner` (one agent task, with failover), `RetryingRunner`,
`PythonTaskRunner`. Queue callbacks: `on_event`, `on_result`, `follow_up`.
A task not launched by the deadline (of a time box it is in), whose remaining
work cannot finish before it, or with every hop on a resting credential, finishes `deferred`: not launched, nothing spent, and no failure
(`RunReport.deferred`, never `RunReport.failed`). `deferred.jsonl` records why (`DeferredRow`): a
`Deferral`, its reason in one line and its cause as data (`DeferralCause`: `deadline`,
`grace_window`, `cannot_finish`, each with the `flow_call` whose time box it was,
`dependency_not_queued`, `rest`, and `dependency_deferred`, with the `dependency` it read,
written by releases before 0.7; `AgentRunner.deferral`); a follow-up task the
queue refuses because its key is in flight finishes `duplicate_key`. A task a
flow waited for that did not succeed raises `TaskFailed` at the `await`
(`TaskDeferred` when it was deferred). A text output a flow receives is a `str`.
