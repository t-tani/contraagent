## A task is a function whose body is a coding agent

<Code
  lang="python"
  title="examples/tutorial/tasks.py"
  code={[
    repoQuote(TASKS, 'class Triage', 'class FixPlan'),
    repoQuote(TASKS, 'triage = agent_task(', 'plan_fix = agent_task'),
    repoQuote(TASKS, 'def triage_one', 'def triage_and_plan'),
  ].join('\n\n\n')}
/>

The coding agent is Claude Code, Codex CLI, opencode, oh-my-pi or pi. How it
does a triage is in the plugin `plugins/triage`, in the coding agent's own
format. The flow is plain Python: a `yield` waits for the checked output, so
loops, branches and fan-outs are ordinary code. Then, in order: every problem
with nothing launched, the whole flow on a stub agent, the run, and the monitor.

```sh
contraagent check tasks.py:triage_all --kwargs '{"reports": ["login-timeout"]}'
contraagent run tasks.py:triage_all --stub --kwargs '{"reports": ["login-timeout"]}'
contraagent run tasks.py:triage_all --config pipeline.toml --kwargs '{"reports": ["login-timeout"]}'
contraagent monitor --runs-dir runs
```

## What the runner does

<CardGrid>
  <Card title="Outputs are contracts">
    Each output file is checked against its pydantic model and its validators. A file that fails goes back to the same agent session with the errors.
  </Card>
  <Card title="Failover and quotas">
    Another model, coding agent or credential after a rate limit or a failed launch, and caps on a subscription's 5-hour and weekly usage.
  </Card>
  <Card title="Deadlines and resume">
    A deadline defers the work that cannot finish, with its cause. A resumed run repeats only the tasks whose inputs or definition changed.
  </Card>
  <Card title="Checked before it spends">
    `contraagent check` reports every problem with nothing launched. A stub agent and recorded replays test a flow with nothing spent.
  </Card>
  <Card title="A clean context per task">
    A task's agent sees its role, its plugin, its skills and its call file, not the user's or the project's settings, nor another task's conversation.
  </Card>
  <Card title="A live monitor">
    The pipeline graph, each task's transcript, inputs, outputs and checks, the history of attempts, and trends over a period. A hub serves the runs of many hosts.
  </Card>
</CardGrid>
