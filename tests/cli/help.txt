$ contraagent --help
usage: contraagent [-h] [--version] {monitor,relay,hub,plugin,call,recording,check,run,docs} ...

positional arguments:
  {monitor,relay,hub,plugin,call,recording,check,run,docs}
    monitor             live web monitor for runs (see `contraagent monitor --help`)
    relay               ship this host's runs to a hub (see `contraagent relay --help`)
    hub                 receive every host's runs and serve their monitor (see `contraagent hub
                        --help`)
    plugin              agent-task plugins: the implementation of an agent task
    call                agent-task call files
    recording           recordings a replay plays (contraagent docs testing, Record once, replay
                        in CI)
    check               check a flow, its plugins and its routing without launching anything
    run                 run a flow, as `check` names it, and report its tasks (for more control,
                        call Pipeline.run from Python)
    docs                the documentation installed with this version: the index, or one topic

options:
  -h, --help            show this help message and exit
  --version             show program's version number and exit

exit status: 0 on success, 1 when the command found a problem or a task failed, 2 on a usage
error; `contraagent <command> --help` says what each command's means

$ contraagent relay --help
usage: contraagent relay [-h] [--runs-dir RUNS_DIR] --hub HUB [--token-file TOKEN_FILE]
                         [--host-id HOST_ID] [--interval INTERVAL] [--ttl TTL] [--since DAYS]
                         [--once] [--progress-file PROGRESS_FILE] [--timeout TIMEOUT]

Ship every run under a runs directory to a contraagent hub, incrementally, and send a heartbeat
with the live runs. The ingest token comes from --token-file, else the environment variable
CONTRAAGENT_HUB_TOKEN; it is never a command line argument.

options:
  -h, --help            show this help message and exit
  --runs-dir RUNS_DIR   the runs directory to ship (default: runs)
  --hub HUB             the hub's address, for example http://hub:8790
  --token-file TOKEN_FILE
                        a file holding the hub's ingest token (default: the environment variable
                        CONTRAAGENT_HUB_TOKEN)
  --host-id HOST_ID     this host's name on the hub (default: CONTRAAGENT_HOST_ID, else the host
                        name)
  --interval INTERVAL   seconds between heartbeats and between passes (default: 3)
  --ttl TTL             seconds the hub counts this host as up after it receives a heartbeat; more
                        than --interval (default: 4 × --interval)
  --since DAYS          of the runs not shipped yet, ship only those whose records changed in the
                        last DAYS days (default: every run)
  --once                make one full pass, then exit: 0 when the hub took everything, else 1
  --progress-file PROGRESS_FILE
                        where the relay keeps how far the hub is in each run (default: <runs-
                        dir>.relay.json, next to the runs directory)
  --timeout TIMEOUT     seconds to wait for each request to the hub (default: 30)

$ contraagent hub --help
usage: contraagent hub [-h] [--store memory|postgres://...]
                       [--blobs memory|dir:PATH|s3://BUCKET/PREFIX] [--streams-dir PATH]
                       [--segments DIR|s3://BUCKET/PREFIX] [--ingest-token-file FILE]
                       [--read-token-file FILE] [--host HOST] [--port PORT] [--allow-host NAME]
                       [--cors-origin ORIGIN] [--base-path PATH] [--title TITLE]
                       [--max-blob-mb MAX_BLOB_MB] [--retain-days N] [--prune-every HOURS]
                       [--openapi [PATH]]
                       {prune} ...

Receive every host's runs from `contraagent relay` and serve their monitor. Tokens are read from
files, never from the command line. Without --read-token-file the monitor (every transcript) is
open to anyone who reaches the port.

options:
  -h, --help            show this help message and exit
  --store memory|postgres://...
                        where records are kept (default: memory)
  --blobs memory|dir:PATH|s3://BUCKET/PREFIX
                        where file contents are kept (default: memory)
  --streams-dir PATH    where task transcripts being written are kept on this host's disk; sealed
                        segments go to --segments (without it transcripts are kept in memory and
                        lost when the hub stops)
  --segments DIR|s3://BUCKET/PREFIX
                        where sealed transcript segments are kept (default: <streams-
                        dir>/segments)
  --ingest-token-file FILE
                        ingest tokens, one per line, or `host_id token` for a token good for that
                        host only
  --read-token-file FILE
                        the token that opens the monitor; without it the monitor is open
  --host HOST
  --port PORT
  --allow-host NAME     also answer monitor requests addressed to this host name (default:
                        localhost, 127.0.0.1, [::1] and the --host address)
  --cors-origin ORIGIN  let a page from this origin read the monitor API, e.g.
                        http://localhost:5173 for a UI dev server
  --base-path PATH      the path a reverse proxy serves the monitor under, e.g. /monitor: the page
                        names it in every URL it reads; the proxy takes it off before it passes a
                        request on (default: none, the monitor is at /)
  --title TITLE
  --max-blob-mb MAX_BLOB_MB
                        the largest blob taken, in MiB (default: 256)
  --retain-days N       remove runs with no activity for N days, while the hub runs (default:
                        $CONTRAAGENT_RETENTION_DAYS; unset or empty: keep every run)
  --prune-every HOURS   hours between prunes; the first is 5 minutes after start (default: 24, or
                        1 when --retain-days is under 7)
  --openapi [PATH]      write the ingest OpenAPI document to PATH (default: stdout) and exit

commands:
  {prune}
    prune               remove old runs from the hub's storage once, without serving

`contraagent hub prune --help`: remove old runs once, without serving.

$ contraagent hub prune --help
usage: contraagent hub prune [-h] [--store memory|postgres://...]
                             [--blobs memory|dir:PATH|s3://BUCKET/PREFIX] [--streams-dir PATH]
                             [--segments DIR|s3://BUCKET/PREFIX] [--retain-days N] [--dry-run]
                             [--blob-grace-hours H] [--json]

Remove the runs with no activity for N days from the hub's storage, once, and print what was
removed. A run is kept while the heartbeats in the store report it live or unresponsive. Do not
run it while a hub started with --retain-days uses the same storage: one process prunes at a time.

options:
  -h, --help            show this help message and exit
  --store memory|postgres://...
                        where records are kept (default: memory)
  --blobs memory|dir:PATH|s3://BUCKET/PREFIX
                        where file contents are kept (default: memory)
  --streams-dir PATH    where task transcripts being written are kept on this host's disk; sealed
                        segments go to --segments (without it transcripts are kept in memory and
                        lost when the hub stops)
  --segments DIR|s3://BUCKET/PREFIX
                        where sealed transcript segments are kept (default: <streams-
                        dir>/segments)
  --retain-days N       remove runs with no activity for N days (default:
                        $CONTRAAGENT_RETENTION_DAYS; one of the two is required)
  --dry-run             remove nothing; report what would be removed
  --blob-grace-hours H  hours a blob no run references is kept after it was stored (default: 24)
  --json                print the report as JSON

$ contraagent run --help
usage: contraagent run [-h] [--config CONFIG] [--kwargs KWARGS] [--agent AGENT] [--model MODEL]
                       [--run-id RUN_ID] [--resume] [--runs-dir RUNS_DIR]
                       [--preflight {substitute,stop,off}] [--stub] [--execute PATTERN]
                       [--record DIR] [--replay DIR] [--record-max-file-mb N] [--record-missing]
                       flow

positional arguments:
  flow                  the flow function: path/to/tasks.py:flow or package.module:flow

options:
  -h, --help            show this help message and exit
  --config CONFIG       the pipeline's TOML file (default: each task's declared defaults)
  --kwargs KWARGS       the flow's keyword arguments, as a JSON object
  --agent AGENT         run every kind on this coding agent, with no failover hops (an override)
  --model MODEL         run every kind on this model, with no failover hops (an override)
  --run-id RUN_ID       the run's id (default: the flow's name)
  --resume              continue the run: skip the tasks it already finished
  --runs-dir RUNS_DIR   where run directories are written (default: runs)
  --preflight {substitute,stop,off}
                        probe every route before the first task; a kind left with no route that
                        answered runs on the first route that answered (substitute) or refuses the
                        run (stop); off: no probe (default: [defaults] preflight, else off)
  --stub                a stub run: the stub agent plays every agent task and every Python task
                        with its output's example (`examples` in the output's JSON Schema; where
                        there is none, the smallest value the schema accepts); no model is called
                        and no Python task's function runs, but those of --execute (run id:
                        <flow>-stub). A task whose example fails a validator ends invalid_output
                        at once, and the last line names those validators
  --execute PATTERN     with --stub or --replay: run the functions of the Python task kinds
                        PATTERN matches instead of playing them: a kind, or an fnmatch pattern of
                        kinds ('*': every Python task, and only the agent tasks are played);
                        repeatable
  --record DIR          write each task attempt's recording to DIR: its outputs, the files its
                        changes= patterns saw change, its transcript and its result
  --replay DIR          a replay: play the recordings in DIR in place of every agent task's launch
                        and every Python task's function (but the kinds of --execute); nothing is
                        spent (run id: <flow>-replay). Not with --stub or --record
  --record-max-file-mb N
                        with --record or --record-missing: keep a recorded file larger than N MB
                        by its SHA-256 and size only (default 4); its task cannot be replayed
  --record-missing      with --replay: a task with no recording in DIR launches (or runs its
                        function) as in any run, and its recording is written into DIR; this can
                        spend tokens

exit status: 0 when the run is ok (RunReport.ok: no task and no flow call failed), 1 when it is
not (in a stub run too: a task whose example fails its validators has failed), or when the run
ends before its first task: the flow raised, or the run was refused (the config, the routing, a
run id that holds a run, the preflight), 2 on a usage error (the flow's name, --kwargs, options
that do not go together)
